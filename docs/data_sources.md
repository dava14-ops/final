# Источники данных для пилотного сбора claims

> **Версия**: 1.0
> **Дата**: 2026-08-15
> **Связанный документ**: `docs/data_contract.md`

## 1. Приоритеты источников

| Приоритет | Источник | Что даёт | Доступ |
|---|---|---|---|
| 1 | Дилеры / сервисные центры | Заказ-наряды, стоимость ремонта, простой, коды ошибок | Договор |
| 2 | Страховые компании | Полисы, выплаты, даты событий, страховые суммы | Договор |
| 3 | Телеметрия (CAN/ISOBUS) | Моточасы, нагрузка, ошибки ECU, GPS | Парк с телематикой |
| 4 | Фермерские хозяйства | Журналы эксплуатации, ремонты | Опрос/анкетирование |
| 5 | МИС | Протоколы испытаний, наработка на отказ | Запрос в архив |

## 2. Детальное описание

### 2.1 Дилеры / сервисные центры (Приоритет 1)

- **Что даёт**: заказ-наряды с деталями ремонта, стоимость нормо-часа,
  время простоя, диагностические коды ошибок.
- **Формат**: выгрузки из 1С, SAP или учётных систем дилера (CSV/Excel).
- **Объём**: 50–200 машин на дилера.
- **Требования**: договор о предоставлении обезличенных данных,
  соглашение о конфиденциальности.
- **Как мапится на data_contract**: `repair_cost`, `downtime_hours`, `failure_system`.

### 2.2 Страховые компании (Приоритет 2)

- **Что даёт**: полисы, выплаты, даты страховых случаев, страховые суммы, франшизы.
- **Формат**: выгрузки из страховых учётных систем.
- **Объём**: 100–1000 полисов.
- **Требования**: договор с актуарным отделом, обезличивание.
- **Как мапится на data_contract**: `claim_amount`, `deductible`, `coverage_limit`, `event_flag`.

### 2.3 Телеметрия CAN/ISOBUS (Приоритет 3)

- **Что даёт**: моточасы, нагрузка двигателя, ошибки ECU, GPS-координаты.
- **Формат**: потоковые данные или CSV-выгрузки с телематических платформ.
- **Объём**: зависит от размера парка с телематикой.
- **Требования**: парк с установленной телематикой, согласие владельца.
- **Как мапится на data_contract**: `hours_at_event`, `peak_load_proxy`.
- **Примечание**: источник `peak_load_proxy` для эндогенного регрессора PeakLoad.

### 2.4 Фермерские хозяйства (Приоритет 4)

- **Что даёт**: журналы эксплуатации, ремонты, простои.
- **Формат**: структурированные анкеты (CSV после оцифровки).
- **Объём**: 10–50 хозяйств.
- **Требования**: опрос/анкетирование, согласие.
- **Как мапится на data_contract**: `age_at_event`, `hours_at_event`, `failure_time`.

### 2.5 МИС — Машиноиспытательные станции (Приоритет 5)

- **Что даёт**: протоколы испытаний, наработка на отказ.
- **Формат**: PDF/сканы, требуется оцифровка.
- **Объём**: исторические данные 2005–2020.
- **Требования**: запрос в архив МИС.
- **Как мапится на data_contract**: MTBF baseline, `failure_system`.
- **Примечание**: источник для валидации `MTBF_BASELINE_HOURS` (1252–1945 мч).

## 3. Рекомендуемая стратегия сбора

1. **Начать с телеметрии** (Приоритет 3), если есть парк с телематикой —
   это даст `peak_load_proxy` для PeakLoad.
2. **Параллельно запросить дилеров** (Приоритет 1) для `repair_cost` и `downtime`.
3. **Дополнить страховыми** (Приоритет 2) для `claim_amount` и `event_flag`.
4. **Использовать МИС** (Приоритет 5) для валидации MTBF baseline.

## 4. Целевые объёмы пилота

| Метрика | Цель |
|---|---|
| Уникальных машин | ≥ 100 |
| Событий (отказов) | ≥ 200 |
| Горизонт наблюдения | ≥ 1712 мч |
| Брендов с ≥ 30 событиями | ≥ 3 |
| Регионов | ≥ 3 |
