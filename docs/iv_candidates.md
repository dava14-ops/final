# Кандидаты инструментов Z для PeakLoad

## 1. Контекст

- **Фаза 3.7 подтвердила** концепцию IV: Work type как инструмент для PeakLoad
  на телеметрии TUM дал **F = 577.67** (порог Stock-Yogo 14.18), R² = 0.292.
- Однако TUM — это немецкие тракторы Fendt **без событий отказов**.
  Для production РФ нужен инструмент, доступный в реальных данных парка
  и удовлетворяющий трём условиям IV.

## 2. Три условия валидного инструмента

| Условие | Формулировка | Как проверяется |
|---|---|---|
| **Релевантность** | corr(Z, PeakLoad) ≠ 0 | F-statistic первой стадии > 14.18 |
| **Исключение** | Z влияет на отказ ТОЛЬКО через PeakLoad | Эконометрическая аргументация + LR-тест |
| **Экзогенность** | corr(Z, U) = 0, где U — неструктурная ошибка | Проверка на симуляции / дизайн исследования |

## 3. Реестр кандидатов

| Кандидат Z | Релевантность | Исключение | Экзогенность | Вердикт | Комментарий |
|---|---|---|---|---|---|
| **Погодное окно / рабочие дни** | Высокая | Высокое | Высокая | ✅ **Основной** | Внешний шок; больше рабочих дней → выше интенсивность → выше PeakLoad; погода не влияет на механический отказ напрямую |
| Размер временного окна | Средняя | Высокое | Высокая | 🟡 Резерв | Перспективен при контроле типа почвы |
| Региональная цена топлива | Средняя | Среднее | Высокая | 🟡 Резерв | Внешний шок, но может косвенно влиять на интенсивность ТО |
| Дефицит подрядной техники | Средняя | Среднее | Средняя | 🟡 Исследовать | Потенциально полезен, но трудно измерить |
| Размер земельного банка | Средняя | Низкое | Средняя | ⚠️ Осторожно | Коррелирует с качеством ТО → риск нарушения исключения |
| Наличие трактора-дублёра | Слабая | Низкое | Средняя | ❌ Слабый | Меняет режим профилактики → нарушение исключения |
| Тип владения (лизинг/собственность) | Слабая | Низкое | Низкая | ❌ Отклонить | Сильно коррелирует с возрастом и обслуживанием |
| Удалённость от сервиса | Средняя | Низкое | Низкая | ❌ Отклонить | Прямое влияние на время/качество ремонта → грубое нарушение исключения |

## 4. Решение

**Основной инструмент для production РФ: `working_days_window`**
(число дней в посевной/уборочной кампании, когда погода позволяла работать).

Обоснование по трём условиям:
1. **Релевантность:** больше рабочих дней → фермер работает интенсивнее,
   чтобы успеть в окно → выше PeakLoad.
2. **Исключение:** погодное окно определяется метеорологией и не влияет
   на механический отказ двигателя напрямую — только через нагрузку.
3. **Экзогенность:** погода не зависит от решений фермера по ТО,
   возраста техники или качества обслуживания.

**Резервный инструмент:** размер временного окна (при условии контроля почвы).

## 5. Порядок валидации

1. **Фаза 5.2** — сбор реальных погодных данных по регионам
   (Росгидромет, NASA POWER, ERA5, NDVI).
2. **Фаза 5.3** — проверка концепции на симуляции:
   F > 14.18, corr(Z, U) ≈ 0, восстановление γ.
3. **Фаза 6** — сбор claims-данных с привязкой региона/года.
4. **Фаза 7** — первая стадия на реальных данных, финальный F-тест.
   Если F < 14.18 → переключение в режим `predictive` (Фаза 5.4).

## 6. Связь с другими фазами

- **Фаза 5.1 → 5.2:** выбранный инструмент определяет схему сбора данных.
- **Фаза 5.1 → 5.4:** результат валидации определяет `iv_mode` (causal / predictive).
